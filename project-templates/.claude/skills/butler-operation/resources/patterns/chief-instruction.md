# メイド長への指示パターン

タスク作成後、メイド長に適切な情報を伝えるための手順。

## 基本原則

1. **必要十分な情報**: 過不足なく、メイド長が判断できる情報を提供
2. **明確な期待**: 何をしてほしいかを明示
3. **コンテキスト提供**: 背景や理由を簡潔に伝達
4. **担当者指定は控える**: 担当者選定はメイド長の責務（BF002回避）

## 通知の基本形式

```bash
maidctl notify chief "メッセージ"
```

## メッセージ構成

### 必須要素

| 要素 | 説明 | 例 |
|------|------|-----|
| タスクID | 作成したタスクの番号 | "#001-003" |
| 概要 | 何のタスクか | "ログイン機能の実装" |

### 推奨要素

| 要素 | 説明 | 例 |
|------|------|-----|
| 優先度 | 急ぎかどうか | "優先度高" |
| 並列可否 | 同時実行できるか | "#001,002は並列可" |
| 依存関係 | 順序がある場合 | "#003は#001,002完了後" |
| 担当希望 | 提案レベルで | "分析得意なメイド推奨" |

## 通知パターン例

### パターン1: 新規タスク群の通知

```bash
maidctl notify chief "新しいタスク #001-004 を作成しました。ログイン機能の実装です。#001,002は並列実行可能、#003,004は順次実行をお願いします。"
```

### パターン2: サブタスクの通知

```bash
maidctl notify chief "#077-1 を作成しました。#077のレビュー指摘への対応です。同じ担当者への割り当てを推奨します。"
```

### パターン3: 緊急タスクの通知

```bash
maidctl notify chief "緊急タスク #010 を作成しました。本番障害対応です。優先度高でお願いします。"
```

### パターン4: 調査タスクの通知

```bash
maidctl notify chief "#020-023 を作成しました。競合調査です。各タスクは独立して並列実行可能です。分析得意なメイドへの割り当てを推奨します。"
```

### パターン5: 既存タスクの活用依頼

```bash
maidctl notify chief "ご主人様から認証機能の指示がありました。既存の #045（スキル候補: 認証パターン）が関連しています。#045 をベースに作業を進めてください。"
```

## 情報量の目安

### 適切な情報量

```
# 良い例: 必要十分
"新しいタスク #001-003 を作成しました。ダッシュボード改修です。
#001(設計)→#002(実装)→#003(テスト)の順序で、各1-2時間の見積もりです。"

# 悪い例: 情報不足
"タスク作りました。"

# 悪い例: 過剰
"新しいタスク #001 を作成しました。これはご主人様からの指示で、
ダッシュボードの表示速度が遅いという問題があり、原因としては
クエリの非効率性、キャッシュの未使用、フロントエンドの... [続く]"
```

## 担当者指定について

### 禁止事項

```bash
# NG: 直接担当者を指定（BF002違反）
maidctl task create --title "調査" --assignees emma

# NG: 強制的な担当者指示
maidctl notify chief "タスク #001 はエマに割り当ててください。"
```

### 許容される表現

```bash
# OK: 提案・推奨レベル
maidctl notify chief "分析得意なメイドへの割り当てを推奨します。"
maidctl notify chief "前回 #045 を担当したメイドが適任かもしれません。"
maidctl notify chief "並列実行のため3名程度の割り当てを想定しています。"
```

## 通知後の動作

```
1. maidctl notify chief でメッセージ送信
2. 停止（ポーリング禁止: BF003）
3. メイド長からの報告または新しい指示を待つ
```

## チェックリスト

通知前の確認:

- [ ] タスクIDを正確に記載したか
- [ ] 何のタスクか概要を含めたか
- [ ] 並列/順次の指示があれば記載したか
- [ ] 緊急度があれば明示したか
- [ ] 担当者を直接指定していないか（提案レベルか）
- [ ] 通知後は停止する準備ができているか
