# ファイルサイズ上限ガイドライン

## 概要

ファイルの肥大化を早期に検知し、保守性の低下を防止する。
1ファイル500行を目安とし、超過時は分割を検討する。

### 背景

- extension.ts（5,309行）やcentral-server.ts（2,816行）のように、単一ファイルが数千行に膨れ上がるとリファクタリングコストが大幅に増大する（task-041調査結果）
- 早期の分割検討により、God Objectパターンの発生を防止できる

## ルール内容

### 必須事項

1. **新規ファイル作成時は500行を上限の目安とする**
   - 500行を超える場合は、責務の分割を検討すること

2. **既存ファイルへの追加時にサイズを意識する**
   - 追加後に500行を超える場合は、分割の検討を報告に記載すること

3. **以下の閾値に基づいて対応する**

   | 行数 | 状態 | 対応 |
   |------|------|------|
   | ~300行 | 正常 | 対応不要 |
   | 300~500行 | 注意 | 責務が複数ないか確認 |
   | 500~800行 | 要検討 | 分割計画を検討し、報告に記載 |
   | 800行~ | 要対応 | 分割を強く推奨。メイド長にエスカレーション |

4. **分割検討時の責務分析**
   - ファイル内の責務（クラス、関数群）を洗い出す
   - 独立して切り出せる単位を特定する
   - 依存関係の方向を確認する（循環参照の防止）

### 推奨事項

1. **1ファイル1責務の原則**
   - 1つのファイルは1つの明確な責務を持つことが望ましい
   - 複数のクラスや無関係な関数群が同居している場合は分割候補

2. **ディレクトリによるモジュール整理**
   - 関連するファイル群はディレクトリにまとめる
   - 例: `utils/`, `services/`, `routes/`, `ui/`

3. **分割時のコミット粒度**
   - ファイル移動は1フェーズ=1コミットで実施
   - ロジック変更とファイル分割は別のコミットにする

4. **テンプレート・HTML埋め込みへの注意**
   - テンプレートリテラル内のCSS/JS/HTMLは行数を大きく膨らませる原因
   - 可能な場合は外部ファイルやテンプレートエンジンの利用を検討

### 禁止事項

1. **500行超過の放置**
   - 500行を超えたファイルに対し、何の検討もなく追加を続けてはならない
   - 「気づいたが分割は不要」という判断は可（理由を報告に記載）

2. **安易な行数削減のためのコード圧縮**
   - 可読性を犠牲にした行数削減（1行に複数文を詰め込む等）は禁止
   - 行数削減は責務の分割によって行うこと

---

## 適用除外

以下のファイルは本ルールの対象外とする:

| ファイル種別 | 理由 |
|-------------|------|
| 自動生成ファイル | 手動管理の対象外 |
| 設定ファイル（JSON/YAML） | 構造上の制約 |
| テストファイル | テストケースの網羅性を優先 |
| 型定義ファイル（.d.ts） | 外部APIの型が大量になる場合がある |

---

## 報告形式

ファイル追加・変更時に500行超過を検知した場合、報告書に以下を記載:

```markdown
## ファイルサイズ超過検知
- ファイル: src/example.ts
- 現在の行数: 620行
- 検知閾値: 500行（要検討）
- 分割候補: あり / なし
- 対応方針: [分割計画を別タスクとして提案 / 現時点では分割不要（理由: ...）]
```
