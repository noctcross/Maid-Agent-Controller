## 概要

タスク完了時や判断が必要な時にご主人様へ報告するための手順。
報告の種類（完了/進捗/判断依頼/問題）に応じた適切な形式とタイミングを提供する。

## 適用条件

- タスクが全て完了し、ご主人様に成果を報告する時
- ブロックが発生し、ご主人様の判断が必要な時
- ご主人様から進捗を聞かれた時
- 予期しない問題が発生し、早期対応が必要な時
- スコープ変更など、承認が必要な事項が発生した時

## 基本原則

1. **簡潔明瞭**: 要点を絞って報告
2. **成果物重視**: 何ができたかを明示
3. **判断依頼は明確に**: 何を決めてほしいかを具体的に
4. **次のアクション提示**: 次に何が必要かを示す

## 報告の種類

| 種類 | タイミング | 内容 |
|------|----------|------|
| 完了報告 | タスク完了時 | 成果物、結果のサマリ |
| 進捗報告 | 求められた時 | 現在の状況、残作業 |
| 判断依頼 | ブロック時 | 選択肢、推奨、判断ポイント |
| 問題報告 | 問題発生時 | 問題内容、影響、対応案 |

## 完了報告の形式

### 基本テンプレート

```
【完了報告】{タスク名}

■ 完了タスク
#001, #002, #003

■ 成果物
- {成果物1の説明}
- {成果物2の説明}

■ 結果サマリ
{1-2文で結果を説明}

■ 次のステップ（あれば）
- {次に必要なアクション}
```

### 例: 機能実装の完了報告

```
【完了報告】ログイン機能の実装

■ 完了タスク
#001 ログインAPI設計・実装
#002 ログインフォームUI実装
#003 認証状態管理実装
#004 統合テスト

■ 成果物
- ログインAPI（POST /api/auth/login）
- ログインフォームコンポーネント
- 認証コンテキスト
- テストコード（カバレッジ85%）

■ 結果サマリ
JWT認証によるログイン機能が完成しました。
ユーザー名・パスワードでログインでき、トークンは24時間有効です。

■ 次のステップ
- ログアウト機能の実装（必要であれば新規タスク作成）
```

## 判断依頼の形式

### 基本テンプレート

```
【判断依頼】{件名}

■ 状況
{現在の状況を簡潔に}

■ 選択肢
1. {選択肢A}: {メリット/デメリット}
2. {選択肢B}: {メリット/デメリット}

■ 推奨
{推奨する選択肢とその理由}

■ 判断ポイント
- {何を基準に決めるべきか}
```

### 例: 技術選定の判断依頼

```
【判断依頼】認証方式の選定

■ 状況
タスク #003（認証実装）がブロックされています。
認証方式の選定でご判断をお願いします。

■ 選択肢
1. JWT認証
   - メリット: スケーラブル、サーバーステートレス
   - デメリット: トークン無効化が難しい

2. セッション認証
   - メリット: 即時無効化可能、実装がシンプル
   - デメリット: サーバー側で状態管理が必要

■ 推奨
JWT認証を推奨します。
理由: 将来的なスケールアウトを考慮すると有利です。

■ 判断ポイント
- セッション即時無効化の要件があるか
- サーバーのスケールアウト計画
```

## 進捗報告の形式

### 基本テンプレート

```
【進捗報告】{プロジェクト/機能名}

■ 完了
- #001 {タスク名} ✅
- #002 {タスク名} ✅

■ 作業中
- #003 {タスク名}（{担当者}、{進捗%}）

■ 未着手
- #004 {タスク名}
- #005 {タスク名}

■ ブロック
- なし / #006: {ブロック理由}

■ 全体進捗
{完了数}/{全体数}（{進捗%}%）

■ 見込み
{完了見込みの説明}
```

## 問題報告の形式

### 基本テンプレート

```
【問題報告】{問題の概要}

■ 問題内容
{何が起きているか}

■ 影響
{どのような影響があるか}

■ 原因（判明している場合）
{原因の説明}

■ 対応案
1. {対応案A}
2. {対応案B}

■ 推奨対応
{推奨する対応とその理由}
```

## 報告タイミング

### すぐに報告すべき場合

| 状況 | 理由 |
|------|------|
| 全タスク完了 | ご主人様が成果を確認できる |
| 重要な判断が必要 | ブロック解消のため |
| 予期しない問題発生 | 早期対応のため |
| スコープ変更の必要性 | 承認が必要 |

### 報告を待つべき場合

| 状況 | 理由 |
|------|------|
| 作業中のタスクがある | 完了を待つ |
| 軽微な問題 | メイド長で対応可能 |
| 技術的な詳細 | 要約して報告 |

## アンチパターン

| アンチパターン | 問題点 | 正しい報告 |
|--------------|--------|-----------|
| 技術詳細の羅列 | ご主人様に不要な情報 | 要約して報告 |
| 判断なし丸投げ | ご主人様の負担増 | 選択肢と推奨を提示 |
| 報告なしで放置 | 状況が伝わらない | 適切なタイミングで報告 |
| 頻繁すぎる報告 | ご主人様の時間を浪費 | まとめて報告 |

## チェックリスト

報告前の確認:

- [ ] 報告の種類（完了/進捗/判断依頼/問題）は明確か
- [ ] 必要な情報が漏れなく含まれているか
- [ ] 不要な詳細を省いているか
- [ ] 判断依頼の場合、選択肢と推奨があるか
- [ ] 次のアクションが明確か
