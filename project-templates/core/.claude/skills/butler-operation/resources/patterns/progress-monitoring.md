# 進捗監視パターン

## 概要

タスクの進捗状況を確認し、必要に応じて対応するための手順。
イベント駆動を原則とし、ポーリングを避けながら適切なタイミングで状況を把握する。

## 適用条件

- ご主人様から進捗を聞かれた時
- ご主人様から長時間報告がないことを指摘された時
- 新しい指示を受ける前に既存タスクの状況を把握したい時
- ブロックされたタスクへの対応が必要な時

## 基本原則

1. **イベント駆動**: ポーリング禁止、報告を待つ
2. **オンデマンド確認**: 必要な時のみ状況を確認
3. **メイド長経由**: 直接メイドに確認しない
4. **状況把握のみ**: 判断・指示はメイド長に委ねる

## 確認コマンド

### タスク一覧の確認

```bash
# 基本（--summary でトークン削減）
maidctl task list --summary

# ステータスでフィルタ
maidctl task list --status pending --summary
maidctl task list --status working --summary
maidctl task list --status blocked --summary

# 担当者でフィルタ
maidctl task list --assignee emma --summary

# 親タスクでフィルタ（サブタスク確認）
maidctl task list --parent 077 --summary
```

### 特定タスクの詳細確認

```bash
# 詳細取得
maidctl task get 077 --summary

# レポート取得（完了タスクの成果物確認）
maidctl team report 077
```

### チーム状況の確認

```bash
# 全メイドのステータス一覧
maidctl team status
```

### ダッシュボード

```
URL: http://localhost:3100/dashboard
- 視覚的な進捗確認
- タスク状態の一覧表示
- ブロック状況の把握
```

## 確認タイミング

### 確認すべき時

| トリガー | 確認内容 |
|---------|---------|
| ご主人様から進捗を聞かれた | `maidctl task list --summary` |
| 長時間報告がない（ご主人様指摘） | `maidctl team status` で状況確認 |
| 新しい指示を受ける前 | 既存タスクの状況を把握 |

### 確認してはいけない時

| 状況 | 理由 |
|------|------|
| 定期的なポーリング | BF003違反 |
| 気になるから | 待機が原則 |
| メイドに直接聞きたい | BF002違反 |

## ステータスの意味

| ステータス | 意味 | 執事の対応 |
|----------|------|-----------|
| `pending` | 未着手 | 待機 |
| `assigned` | 割り当て済み | 待機 |
| `working` | 作業中 | 待機 |
| `completed` | 完了 | レポート確認、ご主人様に報告可能 |
| `blocked` | ブロック | 内容を確認、必要ならご主人様に判断依頼 |

## ブロック対応

### ブロック発見時のフロー

```
1. maidctl task list --status blocked でブロック中タスク確認
2. maidctl task get {ID} でブロック理由を確認
3. 判断が必要な場合:
   a. ご主人様に状況報告
   b. 判断を仰ぐ
   c. 判断結果をメイド長に伝達（必要なら新規タスク作成）
4. 判断不要の場合:
   a. メイド長に状況確認を依頼
```

### ブロック理由の種類

| 種類 | 例 | 対応 |
|------|-----|------|
| 技術的問題 | ライブラリの選定で迷い | メイド長に追加調査を依頼 |
| 要件不明確 | 仕様の詳細が不明 | ご主人様に確認 |
| 外部依存 | APIキーが必要 | ご主人様に手配依頼 |
| 権限問題 | アクセス権がない | ご主人様に手配依頼 |

## 進捗確認例

### 例1: ご主人様から進捗を聞かれた

```bash
# 全体状況を確認
maidctl task list --summary

# 結果をご主人様に報告
"現在の状況です:
- 完了: #001, #002
- 作業中: #003（エマ担当）
- 未着手: #004, #005
全体の40%が完了しています。"
```

### 例2: ブロックの発見と対応

```bash
# ブロック確認
maidctl task list --status blocked --summary

# 詳細確認
maidctl task get 003 --summary

# ご主人様に報告（判断が必要な場合）
"タスク #003 がブロックされています。
理由: 認証方式の選定でJWTとセッションのどちらを使うか判断が必要です。
ご判断をお願いします。"
```

## アンチパターン

| アンチパターン | 問題点 | 正しい対応 |
|--------------|--------|-----------|
| 5分ごとに状況確認 | ポーリング（BF003） | 報告を待つ |
| メイドに直接確認 | 指揮系統違反（BF002） | メイド長経由 |
| 自分でタスク状態を更新 | 責務違反（BF005） | メイド長に依頼 |
| 完了前にレポート要求 | 作業妨害 | completed を待つ |

## チェックリスト

進捗確認時の確認:

- [ ] ご主人様からの要求または正当な理由があるか
- [ ] `--summary` オプションを使用しているか
- [ ] ポーリング的な確認になっていないか
- [ ] 確認後の対応は明確か（報告 or 待機）
