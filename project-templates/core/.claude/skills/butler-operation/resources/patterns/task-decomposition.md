# タスク分解パターン

## 概要

ご主人様からの指示を適切なサブタスクに分解するための手順。
並列実行可能性、適切な粒度、明確な成果物を考慮してタスクを分割する。

## 適用条件

- ご主人様から新しい指示を受けた時
- 既存タスクへの追加指示（レビュー対応、修正依頼など）を受けた時
- 複数のサブタスクに分割が必要な大きな作業を依頼された時
- 依存関係のある複数タスクを整理する必要がある時

## 基本原則

1. **並列実行可能性**: 依存関係のないタスクは分離して並列実行可能に
2. **適切な粒度**: 1タスク = 1メイドが1-2時間で完了できる単位
3. **明確な成果物**: 各タスクに期待される成果物を明記
4. **依存関係の明示**: 順序が必要な場合は明示的に記載

## 分解フロー

```
1. 指示の全体像を把握
   - 何を達成したいか（ゴール）
   - どこまでやるか（スコープ）
   - いつまでか（期限、あれば）

2. 既存タスク・コンテキストの確認
   - maidctl task list で関連タスクを検索
   - .maid-agent/core/context/ で技術スタック等を確認

3. 作業を論理的に分割
   - 調査 → 設計 → 実装 → テスト → レビュー
   - UI / API / DB など層ごと
   - 機能A / 機能B など機能ごと

4. 依存関係の整理
   - 独立して実行可能なタスクを特定
   - 順序が必要なタスクには優先度を設定
```

## タスク作成時の記載項目

### 必須項目

| 項目 | 説明 | 例 |
|------|------|-----|
| `--title` | 簡潔なタスク名 | "ログインAPI実装" |

### 推奨項目

| 項目 | 説明 | 例 |
|------|------|-----|
| `--description` | 詳細説明、成果物定義 | "JWT認証でログインAPIを実装" |
| `--priority` | 優先度 (high/medium/low) | "high" |
| `--parent` | 親タスクID（サブタスクの場合） | "077" |

## 分解パターン例

### パターン1: 機能実装

```
指示: 「ユーザー認証機能を実装して」

分解:
#001 認証方式の調査・選定（JWT vs セッション）
#002 ログインAPI設計・実装
#003 ログアウトAPI実装
#004 認証ミドルウェア実装
#005 フロントエンド認証状態管理
#006 統合テスト作成
```

### パターン2: バグ修正

```
指示: 「ダッシュボードの表示が遅い」

分解:
#001 パフォーマンス計測・ボトルネック特定
#002 クエリ最適化（特定後）
#003 キャッシュ導入検討
#004 修正後の計測・確認
```

### パターン3: リファクタリング

```
指示: 「このファイルを分割して」

分解:
#001 責務分析・分割計画作成
#002 計画レビュー
#003-N 各モジュールへの分割実装（並列可能）
#00X コードレビュー
#00Y 統合テスト
```

### パターン4: 調査・分析

```
指示: 「競合サービスを調査して」

分解:
#001 競合A の調査
#002 競合B の調査
#003 競合C の調査
#004 比較分析・レポート作成
```

### パターン5: 既存タスクへの追加指示

```
指示: 「#077のレビュー結果を反映して」

手順:
1. maidctl task list --status で #077 の状態確認 → completed
2. サブタスク作成:
   maidctl task create --parent 077 --title "レビュー指摘反映"
   → task-077-1 が生成される
3. maidctl notify chief "#077-1 を作成しました。レビュー指摘の反映をお願いします。"
4. 停止

ポイント:
- 親タスクが completed でもサブタスクは作成可能
- 修正・追加調査・レビュー対応は全てサブタスク化
```

### パターン6: 新規指示の完全フロー

```
指示: 「ログイン機能を実装して」

フロー:
1. context/ 確認 → 技術スタック: React + Express
2. 既存タスク確認 → 関連タスクなし
3. 分解:
   #001 ログインAPI設計・実装
   #002 ログインフォームUI実装
   #003 認証状態管理実装
   #004 統合テスト
4. maidctl task create で各タスク作成
5. maidctl notify chief "新しいタスク #001-004 を作成しました。ログイン機能の実装です。"
6. 停止（メイド長の完了報告を待つ）
```

## アンチパターン

### 避けるべき分解

| アンチパターン | 問題点 | 改善案 |
|--------------|--------|--------|
| 1つの巨大タスク | 進捗が見えない、ブロックしやすい | 適切な粒度に分割 |
| 過度に細かい分割 | 管理オーバーヘッド増大 | 論理的な単位でまとめる |
| 依存関係の無視 | 手戻り発生 | 依存関係を明示 |
| 成果物不明確 | 完了判定ができない | 期待する成果物を記載 |

## チェックリスト

タスク作成前の確認:

- [ ] 既存の関連タスクを確認したか
- [ ] 適切な粒度に分割されているか
- [ ] 並列実行可能なタスクを特定したか
- [ ] 依存関係がある場合は明示したか
- [ ] 各タスクの成果物は明確か
- [ ] サブタスクの場合は `--parent` を指定したか
