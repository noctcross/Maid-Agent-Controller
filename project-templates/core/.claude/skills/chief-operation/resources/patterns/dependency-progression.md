# Dependency Progression - 依存関係自動進行

## 概要

ブロッカータスクが完了した際に、依存している後続タスクを自動的に進行させる手順。
タスク間の依存関係を把握し、適切なタイミングで次のタスクを開始させる。

## 適用条件

- タスク完了通知を受けた時、他のタスクがそのタスクの完了を待っていた場合
- `blocked` 状態のタスクがあり、ブロック原因のタスクが完了した時
- 順次実行が必要なタスク群の前段タスクが完了した時
- 調査・設計タスク完了後、実装タスクを開始できる状態になった時

## 基本フロー

```
タスクA完了
    ↓
依存タスク確認（タスクAの完了を待っていたタスクはあるか？）
    ↓
├── あり → 依存タスクを進行
│           ├── pending → assign して通知
│           └── blocked → 状態解除、working へ
│
└── なし → 通常のクローズ処理
```

## 手順

### Step 1: 完了タスクの確認

```bash
# 完了報告を受けたタスクの詳細確認
maidctl task get TASK_ID
```

確認項目:
- タスクID（後続タスクの参照元）
- 親タスクID（サブタスク群の一部か）
- 完了内容（成果物が後続タスクの前提条件を満たしているか）

### Step 2: 依存タスクの特定

依存タスクは以下の方法で特定:

**方法1: 同一親タスクのサブタスク確認**
```bash
# 親タスクの全サブタスク一覧
maidctl task list --parent PARENT_ID --summary
```

**方法2: blocked タスクの確認**
```bash
# ブロック中のタスク一覧
maidctl task list --status blocked --summary
```

**方法3: タスク説明での明示的依存**
- description に「#XXX 完了後に実行」等の記載がないか確認

### Step 3: 依存タスクの進行

**pending 状態のタスクを開始する場合:**
```bash
# 1. タスク割当
maidctl task assign DEPENDENT_ID --to AGENT --title "タイトル"

# 2. メイドへ通知（前提タスク完了を伝える）
maidctl notify {メイド} "#BLOCKER_ID が完了しました。#DEPENDENT_ID を開始してください。"
```

**blocked 状態のタスクを解除する場合:**
```bash
# 1. ブロック解除（サブステータス更新）
maidctl task update DEPENDENT_ID --substatus "ブロック解除: #BLOCKER_ID 完了"

# 2. 担当メイドへ通知
maidctl notify {担当メイド} "#BLOCKER_ID が完了しました。#DEPENDENT_ID の作業を再開してください。"
```

### Step 4: 進行状況の記録

後続タスクを進行させた場合、元タスクの完了報告に追記または別途記録:

```
完了タスク: #XXX
進行させた依存タスク: #YYY, #ZZZ
```

## 判断ポイント

| 状況 | 判断 | 次のアクション |
|------|------|---------------|
| 同一親のサブタスクが pending | 順次実行の次タスク | assign して通知 |
| blocked タスクがこのタスクを参照 | ブロック解除可能 | substatus 更新して通知 |
| 依存タスクなし | 通常完了 | report-collection フロー |
| 依存タスクはあるが別条件もある | 部分的解除 | 条件を確認して判断 |

## 依存関係の種類

| 依存タイプ | 例 | 進行方法 |
|-----------|-----|---------|
| 順次実行 | 設計 → 実装 → テスト | 前段完了で次段を assign |
| ブロック解除 | 調査結果待ち | substatus 更新で再開通知 |
| 並列→集約 | 複数調査 → 比較分析 | 全ブロッカー完了で集約タスク開始 |
| 成果物依存 | API完成 → UI実装 | 成果物確認後に開始 |

## 注意点

- 【重要】依存関係は明示的に管理（推測で進行しない）
- 【禁止】ポーリングで依存タスク完了を監視（CF003違反）
- 【推奨】タスク作成時に依存関係を description に記載
- 【推奨】複雑な依存は親タスクで一元管理

## 事例

### 事例1: 調査→実装の順次実行

**状況**: #101（技術調査）完了、#102（実装）が待機中

**対応**:
```bash
# 調査結果を確認
maidctl task get 101

# 実装タスクを進行
maidctl task assign 102 --to flora --title "API実装"
maidctl notify flora "#101（技術調査）が完了しました。#102 を開始してください。調査結果は reports/current_alice.md を参照。"
```

**結果**: 実装タスクがスムーズに開始、調査結果を活用

### 事例2: 並列タスク完了→集約タスク開始

**状況**: #201, #202, #203（各競合調査）のうち #203 が完了し、全3件が完了状態に

**対応**:
```bash
# 全サブタスク完了を確認
maidctl task list --parent 200 --summary
# → 201: completed, 202: completed, 203: completed

# 集約タスクを作成・開始
maidctl task create --parent 200 --title "競合比較分析レポート"
maidctl task assign 200-4 --to alice --title "競合比較分析"
maidctl notify alice "全調査タスク完了。#200-4 で比較分析をお願いします。"
```

**結果**: 全調査完了を待って集約作業を開始

### 事例3: ブロック解除

**状況**: #301（UI実装）が #300（API完成待ち）でブロック中、#300 が完了

**対応**:
```bash
# ブロック解除
maidctl task update 301 --substatus "ブロック解除: API完成"

# 担当メイドへ通知
maidctl notify flora "#300（API実装）が完了しました。#301 の作業を再開してください。"
```

**結果**: UI実装がスムーズに再開
