# Review Queue Management - レビューキュー運用

## 概要

V2.1で導入されたレビューキューの運用方法。
完了タスクのレビューを効率的に処理し、承認・差し戻しを管理する。

## レビューキューフロー

```
┌─────────────────────────────────────────────────────────────┐
│  レビューキューフロー                                        │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  【メイド】タスク完了                                        │
│      │                                                       │
│      └── maidctl my-status completed                        │
│            │                                                 │
│            ▼                                                 │
│  【システム】                                                │
│      │                                                       │
│      ├── レビューキューに追加                                │
│      ├── 優先度自動設定                                      │
│      └── 自動承認判定                                        │
│            │                                                 │
│            ├── 自動承認条件を満たす → 自動承認               │
│            │                                                 │
│            └── 手動レビュー必要 → キュー待機                 │
│                  │                                           │
│                  ▼                                           │
│  【メイド長】レビュー実施                                    │
│      │                                                       │
│      ├── OK → 承認（reviewStatus: approved）                │
│      │                                                       │
│      └── NG → 差し戻し（reviewStatus: rejected）            │
│                  │                                           │
│                  └── 修正サブタスク作成                      │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

## 自動承認条件

以下の**全条件**を満たす場合、自動承認される:

| 条件 | 閾値 | 備考 |
|------|------|------|
| 変更ファイル数 | <= 3 | 少量変更 |
| 変更行数 | <= 100 | 軽微な修正 |
| テストあり | true | テストが書かれている |
| タスク種別 | action | Action タスクのみ |
| セキュリティファイル変更 | なし | .env, credentials 等 |
| 設定ファイル変更 | なし | config.*, *.yaml 等 |

## 手順

### Step 1: レビューキュー確認

```bash
# レビュー待ちタスク一覧
maidctl review list

# 優先度順に表示される
# - high: 他タスクがblocked、ご主人様指示
# - normal: 通常
# - low: simple Goal、軽微な変更
```

### Step 2: レビュー実施

```bash
# タスク詳細確認
maidctl task get TASK_ID

# 報告書確認
# reports/current_{メイド}.md

# 変更内容確認（成果物パス）
# 報告書内の artifacts セクション参照
```

### レビュー観点

| 観点 | 確認内容 |
|------|----------|
| 要件充足 | タスクの要件を満たしているか |
| コード品質 | 可読性、保守性、命名規則 |
| テスト | テストが適切に書かれているか |
| セキュリティ | 脆弱性、機密情報の露出 |
| パフォーマンス | 明らかな問題がないか |

### Step 3: 承認または差し戻し

**承認する場合:**
```bash
maidctl task update TASK_ID --review-status approved

# 完了通知（任意）
maidctl notify {メイド} "#TASK_ID 承認しました。お疲れ様でした。"
```

**差し戻しする場合:**
```bash
# 1. 修正サブタスク作成
maidctl task create --parent PARENT_ID --title "修正: [指摘内容]"

# 2. 元タスクのレビュー状態更新
maidctl task update TASK_ID --review-status rejected

# 3. 修正タスク割当
maidctl task assign NEW_TASK_ID --to {メイド} --title "修正作業"

# 4. メイドへ通知
maidctl notify {メイド} "#TASK_ID にレビュー指摘があります。#NEW_TASK_ID で修正をお願いします。指摘内容: [詳細]"
```

## 優先度管理

### 優先度の自動設定

| 条件 | 優先度 | 理由 |
|------|--------|------|
| 他タスクが blocked | high | 依存解消を優先 |
| ご主人様指示タスク | high | 重要タスク |
| standard/complex Goal | normal | 通常 |
| simple Goal | low | 軽微な変更 |

### 優先度の手動調整

緊急度に応じて優先度を変更:
```bash
maidctl task update TASK_ID --priority high
```

## ピアレビュー委任

負荷分散のため、他メイドにレビューを委任:

```bash
# レビュー担当をメイドに委任
maidctl notify {レビュー担当メイド} "#TASK_ID のコードレビューをお願いします。"
```

**委任基準:**
- 軽微な変更（変更100行以下）
- Actionタスク（PhaseやGoalは委任しない）
- セキュリティ/設定変更なし

詳細は [peer-review](peer-review.md) パターンを参照。

## 判断ポイント

| 状況 | 判断 | アクション |
|------|------|-----------|
| 自動承認済み | 確認のみ | 対応不要 |
| 軽微な変更 | 承認 | 迅速に承認 |
| 要修正あり | 差し戻し | 修正サブタスク作成 |
| 判断困難 | エスカレーション | ご主人様に確認 |

## 注意点

- 【重要】差し戻し時は必ず修正サブタスクを作成
- 【禁止】レビューなしでのタスククローズ（自動承認を除く）
- 【推奨】高優先度は24時間以内にレビュー
- 【推奨】差し戻し理由は具体的に記載

## レビュー滞留時の対応

```bash
# 滞留確認（3日以上キュー待ち）
maidctl review list --pending-days 3

# 対応
# - 優先度見直し
# - ピアレビュー委任
# - 一時的なキューフリーズ（大量滞留時）
```
