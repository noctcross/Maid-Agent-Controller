# checkpoint vs waiting - 使い分けガイド（V2.1）

## 概要

V2.1で導入された2つの待機状態の使い分けを明確にするガイド。
正しく使い分けることで、依存解消時の自動通知や、エスカレーション管理が効率化される。

## 適用条件

- タスク実行中に外部要因で進められなくなった時
- 何かの完了・決定を待つ必要がある時

## 2つの待機状態

| 状態 | 待機対象 | 解消方法 | 通知 |
|------|---------|---------|------|
| checkpoint | 人間の判断・決定 | 上位者が回答 | 手動通知 |
| waiting | 他タスクの完了 | 依存タスク完了 | **自動通知** |

## checkpoint（ご主人様/上位者の判断待ち）

### いつ使うか

- **技術的な重要決定**が必要な場合
  - アーキテクチャの選択（例: 認証方式、データベース選定）
  - 破壊的変更の承認
  - セキュリティ関連の判断

- **ビジネス判断**が必要な場合
  - 仕様の確定・変更
  - 優先度の決定
  - リソース配分

- **外部への確認**が必要な場合
  - 外部APIの利用可否
  - ライセンス・著作権の確認
  - 他チームとの調整

### コマンド

```bash
maidctl my-status blocked --substatus checkpoint --reason "判断を仰ぐ内容"
```

### 報告書の記載

```yaml
## エスカレーション
escalation:
  required: true
  title: "認証方式の選択"
  detail: |
    OAuth/JWT/Sessionの3択があります。
    - OAuth: セキュリティ高、実装コスト高
    - JWT: バランス型、スケーラブル
    - Session: シンプル、ステートフル
    ご判断をお願いいたします。
```

## waiting（他タスクの完了待ち）

### いつ使うか

- **前提タスクが未完了**の場合
  - 依存するモジュールの実装待ち
  - 前段階のテスト完了待ち
  - 設計ドキュメントの作成待ち

- **並行タスクの成果物が必要**な場合
  - 他メイドの実装結果を参照する必要がある
  - 共有リソースの準備待ち

- **外部タスクの完了待ち**の場合
  - CI/CDパイプラインの完了待ち
  - 外部サービスのデプロイ待ち

### コマンド

```bash
maidctl my-status blocked --substatus waiting --blocked-by TASK_ID
```

複数タスクに依存する場合:
```bash
maidctl my-status blocked --substatus waiting --blocked-by task-100-2,task-100-3
```

### 報告書の記載

```yaml
## 問題・注意点
依存タスク task-100-2（単体テスト実装）の完了を待機中。
完了後、統合テストを実行予定。
```

```
       │

             │
    ┌────────┴────────┐

    │                 │

```

## よくある間違い

### 間違い1: 全部 blocked にする

```bash
# 悪い例: 旧来の blocked を使い続ける
maidctl my-status blocked --summary "待機中"
```

**問題**: 自動通知の恩恵を受けられない、判断待ちと依存待ちの区別がつかない

**改善**: 待機の種類を判断して checkpoint か waiting を使用

### 間違い2: checkpoint で依存待ち

```bash
# 悪い例: タスク完了待ちを checkpoint にする
maidctl my-status blocked --substatus checkpoint --reason "task-100-2 の完了待ち"
```

**問題**: 依存解消時の自動通知が発動しない、メイド長が手動で通知する必要がある

**改善**: `maidctl my-status blocked --substatus waiting --blocked-by task-100-2`

### 間違い3: waiting で判断待ち

```bash
# 悪い例: 人間の判断を waiting にする
maidctl my-status blocked --substatus waiting --blocked-by task-999
# （存在しないタスクIDを指定）
```

**問題**: 依存解消が永遠に発生しない、エスカレーションが正しく行われない

**改善**: `maidctl my-status blocked --substatus checkpoint --reason "判断内容"`

## 実例比較

### 例1: 認証方式の選択

```
状況: OAuth, JWT, Session のどれを使うかご主人様に聞きたい

→ checkpoint を使用
理由: 人間（ご主人様）の判断が必要
```

### 例2: 単体テスト完了待ち

```
状況: 統合テストを実行したいが、単体テスト（task-100-2）がまだ

→ blocked --substatus waiting --blocked-by task-100-2 を使用
理由: 他タスクの完了を待つだけ、判断は不要
```

### 例3: 外部API仕様の確認待ち

```
状況: 外部APIの仕様を外部チームに確認中

→ checkpoint を使用
理由: 外部からの回答（人間の応答）を待つ
```

### 例4: CI完了待ち

```
状況: CIパイプラインがビルド中、完了後にデプロイしたい

→ waiting を使用（CIタスクがtasks.yamlに登録されている場合）
→ checkpoint を使用（タスク管理外の場合）
```
