# Release Checklist Pattern

## 概要

VSCode拡張機能のリリース前チェックリストと手順。
バージョンアップ時の設定継続性やMCP互換性の確認を含む。

## 適用条件

- 拡張機能の新バージョンをリリースする時
- マーケットプレイスに公開する時
- vsixパッケージを配布する時
- 大きな機能変更を含むアップデート時

## チェックリスト

### 1. コード・ビルド確認

- [ ] TypeScriptコンパイルエラーなし
- [ ] ESLintエラー・警告なし
- [ ] すべてのテストがパス
- [ ] 開発用コード（console.log等）を削除

```bash
# ビルド確認
npm run compile
npm run lint
npm test
```

### 2. package.json 更新

- [ ] `version` をインクリメント（セマンティックバージョニング）
- [ ] `engines.vscode` が対応VSCodeバージョンと一致
- [ ] `dependencies` / `devDependencies` が最新・安全
- [ ] `contributes` の設定が正しい

```json
{
  "version": "1.2.0",
  "engines": {
    "vscode": "^1.80.0"
  }
}
```

### 3. 設定継続性確認

既存ユーザーの設定が新バージョンでも動作するか確認:

- [ ] 設定キー名の変更がないか
- [ ] 設定のデフォルト値変更の影響
- [ ] 非推奨設定のマイグレーション手順
- [ ] `configuration` スキーマの後方互換性

### 4. MCP互換性確認（該当する場合）

MCP（Model Context Protocol）サーバーを含む拡張の場合:

- [ ] MCPサーバーの起動・停止が正常
- [ ] ツール登録・実行が正常
- [ ] エラーハンドリングが適切
- [ ] 設定変更後の再接続が正常

### 5. vsixパッケージ作成・検証

```bash
# パッケージ作成
npx @vscode/vsce package

# 生成されたvsixファイルを確認
ls -la *.vsix

# ローカルインストールテスト
code --install-extension ./extension-name-1.2.0.vsix
```

検証項目:
- [ ] vsixが正常に生成される
- [ ] ファイルサイズが妥当（急激な増加がないか）
- [ ] ローカルインストールが成功
- [ ] 主要機能が動作

### 6. CHANGELOG更新

- [ ] 新機能を追加
- [ ] バグ修正を記載
- [ ] 破壊的変更を明記
- [ ] 日付とバージョンを記載

```markdown
## [1.2.0] - 2026-02-14

### Added
- 新機能Xを追加

### Fixed
- バグYを修正

### Changed
- 設定Zのデフォルト値を変更
```

### 7. ユーザー向け推奨手順

アップデート後のユーザー向け手順を準備:

1. **拡張機能を更新**
   - マーケットプレイス / vsix から最新版をインストール

2. **VSCodeを再起動**
   - 拡張機能の再読み込みを確実に

3. **設定を確認**（必要な場合）
   - 新しい設定項目を確認
   - 非推奨設定の移行

4. **動作確認**
   - 主要機能が正常に動作するか

## 注意点

### リリース前の最終確認

| 確認項目 | 確認方法 |
|---------|---------|
| パッケージサイズ | `ls -la *.vsix` で急激な増加がないか |
| 依存関係 | `npm audit` でセキュリティ問題がないか |
| ライセンス | 依存パッケージのライセンス確認 |
| README | マーケットプレイスでの表示を確認 |

### ロールバック準備

- 前バージョンのvsixを保持
- 問題発生時のダウングレード手順を準備

## 事例

### 事例1: v1.1アップデート（#168）

**内容**: MCPサーバー改善、設定UI追加
**確認事項**:
- MCPサーバーの再起動確認
- 既存設定の継続性確認
- 新規設定のデフォルト値確認

**ユーザー向け手順**:
1. 拡張機能を更新
2. VSCodeを再起動
3. MCPサーバーが自動再接続されることを確認
