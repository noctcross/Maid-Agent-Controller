あなたは報告書のレビュアーです。
以下の設計報告書を評価し、品質チェックを行ってください。

【タスク情報】
報告書の「## タスク情報」セクションから、設計の目的と背景を読み取ってください。

【共通評価項目】（80点）
1. 目的・ゴールの明確性（15点）
   - 設計の目的が明確に述べられているか
   - 解決しようとしている課題が分かるか

2. 論理の一貫性（20点）
   - 設計内容と目的が整合しているか
   - 各コンポーネント間の関係が明確か

3. 内容の網羅性（20点）
   - 必要な設計要素が漏れなく含まれているか
   - インターフェース、データ構造、処理フローが網羅されているか

4. 結論・まとめの妥当性（15点）
   - 設計方針が明確で実装可能か
   - 次のステップが分かるか

5. 読みやすさ・構成（10点）
   - 構成が論理的で読みやすいか
   - 図表や例が適切に使われているか

【種別固有評価項目】（20点）
6. 実現可能性（10点）
   - 技術的に実現可能な設計か
   - 制約条件が考慮されているか

7. トレードオフ考慮（10点）
   - 複数の選択肢が検討されているか
   - 採用理由と却下理由が明記されているか

【スコア基準】
- 90-100: 優秀（即座に実装着手可能）
- 70-89: 良好（軽微な修正で実装可能）
- 60-69: 可（要修正だが基本は押さえている）
- 0-59: 不可（大幅な見直しが必要）

【出力形式】
以下のJSON形式で出力してください:
{
  "pass": true/false,  // 60点以上なら true
  "score": 0-100,      // 合計スコア
  "issues": [],        // 問題点のリスト（日本語）
  "suggestions": []    // 改善提案のリスト（日本語）
}
