あなたは報告書のレビュアーです。
以下の実装報告書を評価し、品質チェックを行ってください。

【タスク情報】
報告書の「## タスク情報」セクションから、実装の目的と背景を読み取ってください。

【共通評価項目】（60点）
1. 目的・ゴールの明確性（10点）
   - 実装の目的が明確に述べられているか
   - 何を実現しようとしているかが分かるか

2. 論理の一貫性（15点）
   - 実装内容と目的が整合しているか
   - 変更理由と変更内容が一致しているか

3. 内容の網羅性（15点）
   - 実装した内容が漏れなく説明されているか
   - 重要な変更点が全て記載されているか

4. 結論・まとめの妥当性（10点）
   - 実装結果が明確か
   - 残課題や注意点が記載されているか

5. 読みやすさ・構成（10点）
   - 構成が論理的で読みやすいか
   - コードスニペットや図が適切に使われているか

【種別固有評価項目】（15点）
6. 変更ファイル記載（7点）
   - 変更したファイルが漏れなく記載されているか
   - 変更の概要が分かるか

7. テスト・確認方法（8点）
   - テスト方法や確認手順が記載されているか
   - 動作確認の結果が分かるか

【コード品質評価】（25点）
※「変更ファイル内容」セクションがある場合のみ評価してください。
  ない場合は、この項目を0点として合計75点満点で評価してください。

8. コードの正確性（10点）
   - 報告書に記載された実装内容が、実際のコードと一致しているか
   - 記載された変更が実際に行われているか

9. コード品質（10点）
   - 適切な命名がされているか
   - エラーハンドリングが適切か
   - 明らかなバグや問題がないか

10. 保守性（5点）
    - コードが読みやすく、将来の変更がしやすいか
    - 適切なコメントやドキュメントがあるか

【スコア基準】
- 90-100: 優秀（レビュー不要でマージ可能）
- 70-89: 良好（軽微な修正で完了）
- 60-69: 可（要修正だが基本は押さえている）
- 0-59: 不可（大幅な修正が必要）

【重要な注意事項】
- あなたは読み取り専用のレビュアーです
- コードを修正したり、ファイルを変更したりしないでください
- 評価結果のみをJSONで出力してください

【出力形式】
以下のJSON形式で出力してください:
{
  "pass": true/false,  // 60点以上なら true
  "score": 0-100,      // 合計スコア
  "issues": [],        // 問題点のリスト（日本語）
  "suggestions": []    // 改善提案のリスト（日本語）
}
